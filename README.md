# MedStep — банк вопросов USMLE на русском

Готовый сайт для подготовки к USMLE Step 1, Step 2 CK и Step 3: регистрация и оплата доступа, создание тестов, экзаменационный интерфейс, разборы, статистика, заметки, флеш-карты и админка для авторов вопросов.

Проект не требует установки пакетов: только **Node.js 22.13 или новее**. База данных — встроенный в Node SQLite (один файл), картинки хранятся рядом в папке `data/uploads`.

## Быстрый старт на своём компьютере

```bash
cp .env.example .env          # укажите ADMIN_EMAIL и ADMIN_PASSWORD
npm start                     # сайт откроется на http://localhost:3000
```

При первом запуске:
- создаётся администратор из `.env`;
- в пустую базу добавляются 22 демо-вопроса (оригинальные, на русском), чтобы сразу проверить работу. Удалите или архивируйте их в админке, когда загрузите свои; чтобы не добавлять их вовсе — `SEED_DEMO=0`.

Полезные команды:

| Команда | Что делает |
|---|---|
| `npm run dev` | запуск с перезапуском при изменении кода |
| `npm run make-admin -- email@site.kg пароль` | сделать пользователя администратором (или создать нового) |
| `npm run backup` | резервная копия базы в `data/backups/` |
| `npm run seed` | добавить демо-вопросы ещё раз |

## Что умеет сайт

**Для студентов**
- Создание теста: Step, режим (Tutor — разбор сразу; Timed — 90 секунд на вопрос, разбор в конце), фильтры «неиспользованные / неверные / отмеченные / пропущенные / верные», предметы и системы с количеством доступных вопросов, до 40 вопросов в блоке.
- Экзаменационный интерфейс: навигатор по блоку, таймер, отметки (флажок), жёлтый маркер для текста условия, зачёркивание вариантов правым кликом, лабораторные нормы, калькулятор, размер шрифта, тёмная тема, горячие клавиши (A–J, Enter, ←/→, M). Тест можно прервать и продолжить с любого устройства.
- Разбор: верный ответ, процент пользователей, выбравших каждый вариант, объяснение, цель обучения, заметка к вопросу, флеш-карта в один клик.
- Результаты теста, общая статистика по предметам и системам, график результатов, сброс прогресса.
- Флеш-карты с интервальными повторениями (упрощённый алгоритм SM-2), колоды.
- Пробный доступ: без оплаты открыты вопросы с пометкой «пробный».

**Для авторов и администраторов** (раздел «Администрирование» в меню)
- Редактор вопроса с живым предпросмотром, загрузкой картинок, черновиками и публикацией.
- Импорт из CSV или JSON (шаблоны — в разделе «Импорт и экспорт»), экспорт всей базы в JSON.
- Предметы и системы, массовые действия (публикация, архив, пробные вопросы).
- Пользователи: продление доступа, роли, блокировка, сброс пароля.
- Оплаты: пользователь выбирает тариф, видит ваши реквизиты и оставляет данные платежа; вы подтверждаете заявку — доступ продлевается автоматически.
- Тарифы, название сайта, контакты, инструкция по оплате.

Роли: **студент** — решает вопросы; **автор** — плюс управление вопросами; **администратор** — всё, включая пользователей и оплаты.

## Наборы вопросов в коде

В папке `server/content/` лежат наборы оригинальных вопросов в формате JSON (сейчас — 52 вопроса Step 1 по всем системам). При каждом запуске сайт добавляет из них вопросы, которых ещё нет в базе (по полю `key`). Поэтому они не пропадают даже на хостинге без постоянного диска, а правки, сделанные в админке, не перезаписываются. Удалённый в админке вопрос из набора переносится в архив. Отключить загрузку наборов: `CONTENT_PACKS=0`.

Вопросы составлены с помощью ИИ и должны пройти проверку врача перед использованием для платного обучения.

## Как добавлять вопросы

1. Войдите администратором → «Вопросы» → «Новый вопрос», или загрузите файл в «Импорт и экспорт».
2. Текст поддерживает простую разметку: `**жирный**`, `*курсив*`, списки через `- `, таблицы через `|` (удобно для анализов в условии), картинки `![](/uploads/файл.png)`.
3. Новые вопросы сохраняются черновиками и видны студентам только после публикации.

Формат CSV: столбцы `step, subject, system, topic, difficulty, is_free, stem, question, option_a … option_j, correct, explanation, objective, image`. В `correct` — буква правильного ответа. Сохраняйте файл в UTF-8.

> **О контенте.** Используйте только вопросы, на которые у вас есть права: написанные вашими авторами или полученные по лицензии. Копирование вопросов коммерческих банков (UWorld, AMBOSS, NBME и т.п.) нарушает их авторские права и может привести к блокировке сайта и претензиям.

## Публикация в интернете (VPS + Docker)

Подойдёт любой VPS с 1 ГБ памяти (Hetzner, DigitalOcean, местные хостинги). Нужен домен, направленный на IP сервера.

```bash
# на сервере
git clone <ваш-репозиторий> qbank && cd qbank     # или загрузите архив
cp .env.example .env && nano .env                # ADMIN_EMAIL, ADMIN_PASSWORD, SITE_NAME
docker compose up -d --build
```

HTTPS проще всего через [Caddy](https://caddyserver.com) — он сам получает сертификат. Файл `/etc/caddy/Caddyfile`:

```
ваш-домен.kg {
    reverse_proxy 127.0.0.1:3000
}
```

В `.env` оставьте `TRUST_PROXY=1` и `COOKIE_SECURE=1` (сайт за прокси и с HTTPS).

Без Docker: установите Node.js 22 LTS, запустите `npm start` через systemd или `pm2`, тот же Caddy впереди.

### Обновления на Render

Сайт подключён к Render через GitHub-приложение Render: каждый новый коммит в ветку `main` автоматически пересобирает и перезапускает сайт (Settings → Build & Deploy → Auto-Deploy: On Commit). Вручную сборку можно запустить кнопкой «Manual Deploy → Deploy latest commit».

### Резервные копии

Всё состояние сайта — в папке данных (`data/` или том `qbank-data` в Docker): файл `qbank.db` и папка `uploads`. Делайте копию хотя бы раз в сутки, например cron-задачей:

```bash
0 4 * * * cd /root/qbank && docker compose exec -T qbank node --disable-warning=ExperimentalWarning server/cli.js backup
```

и периодически выгружайте `data/backups` за пределы сервера. Экспорт вопросов в JSON из админки — ещё одна страховка для контента.

## Безопасность

- Пароли хранятся как scrypt-хеши, сессии — в HttpOnly-cookie с SameSite=Lax, при HTTPS — Secure.
- Ограничение попыток входа и регистрации, проверка Origin для изменяющих запросов, строгая Content-Security-Policy.
- Правильные ответы и объяснения не отдаются браузеру до того, как вопрос отвечен (Tutor) или блок завершён (Timed).
- Весь пользовательский текст экранируется; разметка в вопросах ограничена безопасным набором.

## Что можно добавить дальше

- Автоматическая оплата (Stripe, FreedomPay, PayBox, Mbank API) вместо ручного подтверждения: обработчик платежа должен вызывать ту же логику, что `POST /api/admin/orders/:id/decide`.
- Восстановление пароля по email (нужен SMTP-сервис).
- Ограничение одновременных сессий на аккаунт, если важна защита от передачи доступа.
- Самостоятельный хостинг шрифта Onest (сейчас подключается с Google Fonts).
